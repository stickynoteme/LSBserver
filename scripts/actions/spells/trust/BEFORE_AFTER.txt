WORKFLOW COMPARISON:
===================

BEFORE - Creating/Editing a Trust:
-----------------------------------
1. User opens trust_editor.py
2. Selects "curilla.lua"
3. Sees BLANK FORM (no guidance)
4. Must manually add all gambits, mods, settings
5. Must research what values to use
6. Saves → creates userdata/curilla.json
7. If mistakes made → must manually fix or delete file

Problems:
• Time-consuming
• Requires extensive knowledge
• No examples
• Error-prone
• Can't easily undo changes


AFTER - Creating/Editing a Trust:
----------------------------------
Scenario A: First Time Use
1. User opens trust_editor.py
2. Selects "curilla.lua"
3. Sees DEFAULT CONFIGURATION automatically:
   - 3 gambits (Sentinel, Flash, Cure)
   - Auto-attack enabled
   - Proper structure
4. User can modify as needed or use as-is
5. Saves → creates userdata/curilla.json

Scenario B: Restoring Defaults
1. User has modified "curilla.lua"
2. Wants to undo changes
3. Clicks "Restore to Default"
4. Confirms → default config loaded from sys/defaults/

Scenario C: Starting Fresh
1. User wants blank slate
2. Clicks "Clear All"
3. Confirms → all fields cleared
4. Builds custom configuration

Benefits:
• Faster setup
• Working examples provided
• Less error-prone
• Easy to undo changes
• Flexible workflow
