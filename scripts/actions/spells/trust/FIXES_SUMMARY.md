# Trust System Fixes - Complete Summary

## Issues Fixed

### 1. Default Configuration Not Loading (zeid.lua)
**Problem**: Error message "No default configuration found for zeid.lua" when trying to restore.

**Root Cause**: Filename handling bug where the code was looking for "zeid.lua.json" instead of "zeid.json"
- `get_trust_files()` returns filenames with `.lua` extension: ["zeid.lua", "lion.lua", ...]
- Code was doing: `filename + ".json"` → `"zeid.lua.json"` ❌
- Should be: `filename.replace('.lua', '') + ".json"` → `"zeid.json"` ✓

**Fix**: Updated all methods to strip `.lua` extension before constructing JSON paths:
- `on_trust_selected()` - Loading defaults when selecting a trust
- `save_trust()` - Saving user configurations
- `restore_to_default()` - Restoring to defaults
- `clear_all()` - Clearing all values

### 2. Nothing Loaded Into Editor
**Problem**: When restoring defaults, the editor remained blank.

**Root Cause**: Same filename handling bug prevented default files from being found.

**Fix**: With the filename fix above, defaults now load correctly into the editor.

### 3. Job Templates Clear Faux Gear
**Problem**: Applying a job template would reset ALL data including gear, which users wanted preserved.

**Solution**: Modified `apply_job_template()` to:
1. Save current gear before resetting form
2. Apply job template (mods, gambits, etc.)
3. Restore saved gear back to form
4. Updated confirmation dialog to mention gear preservation

### 4. Lion.lua Not Working In-Game
**Problem**: Lion trust wasn't behaving like a WHM despite the Lua file showing correct setup.

**Root Causes**:
1. **Mismatched defaults**: lion.json had invalid ranger-style setup with "kGrapeshot" instead of WHM configuration
2. **Redundant require statements**: Generated files had unnecessary `require()` calls that could cause loading issues

**Fixes**:
1. Added gear parsing to `generate_defaults.py` to capture `mob:setLook({})` statements
2. Regenerated all 120 trust defaults with proper parsing
3. Removed redundant `require()` statements from generated Lua
4. Regenerated lion.lua and aaev.lua to match standard trust format

## Why Require Statements Were Problematic

1. **Already Loaded**: `scripts/globals/trust.lua` already requires `scripts/globals/magic.lua`
2. **Standard Format**: All vanilla trusts don't have require statements
3. **Circular Dependencies**: Could cause issues in Lua's module system
4. **Redundancy**: Trust system automatically provides necessary context
